# AC-5: `sub_agent_invocations` Field — Spec Evidence

**AC**: AC-5 from v0.1.11 Stage 1 charter  
**Dispatch**: V0.1.11-S1-EX3 (PO PM EXECUTING)  
**Branch**: feat/v0.1.11-real-claude-integration  
**Status**: LANDED

---

## §rationale

RAID item `RAID-V11-pm-subagent-disclosure` identified a governance gap: PM dispatches could Task-dispatch sub-agents without any trace in their return payload. TeamLead had no way to audit whether sub-agent usage complied with Hard Rule 8 (parallel-dispatch requires PlanAudit approval). This gap also has a security dimension (LL-SEC-5): undisclosed sub-agent invocations could silently inherit PM trust-tier and consume budget outside the tracking window.

The `sub_agent_invocations` field closes this gap by requiring PMs to declare every sub-agent they dispatched, with enough metadata for TeamLead to verify PlanAudit approval. This dispatch also demonstrates good-faith compliance: this PO dispatch itself emits `sub_agent_invocations: []` (no sub-agents dispatched).

---

## §field-schema

The field is a JSON array of objects appended at the top level of the return contract:

```json
"sub_agent_invocations": [
  {
    "subagent_type": "general-purpose | opus-reviewer | rd-pm | po-pm | qa-pm | ux-pm | ad-hoc-pm",
    "scope": "<one-line task description, ≤120 chars>",
    "justification": "<why dispatch was necessary, referencing approved plan parallel-dispatch declaration>",
    "planaudit_approval_ref": "<PROGRESS.md anchor e.g. PROGRESS.md#stage-1-planaudit, or null>"
  }
]
```

### Sub-field validation rules

(a) `subagent_type` MUST be one of the enum values (matching Hard Rule 8 PM agent list):
    `general-purpose`, `opus-reviewer`, `rd-pm`, `po-pm`, `qa-pm`, `ux-pm`, `ad-hoc-pm`

(b) `planaudit_approval_ref` when non-null SHOULD reference a `PROGRESS.md ## Stage History ### Stage X PlanAudit` anchor. TeamLead verifies the referenced PlanAudit approved the parallel-dispatch pattern.

(c) Empty array `[]` is valid — it means no sub-agents were dispatched in this dispatch.

## §rule-0-extension

`anti-rubber-stamp.md §Rule 0` was extended with Step 0.X (appended after step 4 in the existing Rule 0 flow):

### Trigger A — missing field on parallel-dispatch

Condition: dispatch was declared as parallel-dispatch in the approved plan AND return JSON lacks `sub_agent_invocations` field.

Action: return INCOMPLETE, cite "sub_agent_invocations field missing on parallel-dispatch". Re-dispatch once.

Retry pool: 1-retry pool **distinct** from:
- Schema-validation retry pool (per `dispatch-header.md` §Return contract line 132)
- Step-review retry pool
- Mini Gate retry pool

Legacy exemption: dispatches started before v0.1.11 rollout are exempt; TeamLead logs `sub_agent_invocations: legacy_exempt` in `audit-trail.jsonl` notes.

### Trigger B — unapproved non-trivial sub-agent

Condition: any entry in `sub_agent_invocations` has `planaudit_approval_ref: null` AND `subagent_type` is not in the trivial-list.

Trivial-list: initially **empty** — every sub-agent invocation must have a PlanAudit approval reference at launch. The trivial-list may be expanded via CCB-Light if operational experience identifies genuinely trivial sub-agent types.

Action: return INCOMPLETE, cite the specific entry. Re-dispatch once.

Retry pool: same Trigger-B pool, distinct from Trigger A pool.

## §persistence

### `docs/sub-agent-invocations.jsonl`

Full 4-field array per dispatch. Schema per file header comment:

```
{dispatch_id: string, parent_pm: string, sub_agent_invocations: [...]}
```

TeamLead appends one row per dispatch that declares `sub_agent_invocations`. Rows with empty arrays `[]` are written when no sub-agents were dispatched. Legacy dispatches (pre-v0.1.11) are exempt and do not appear.

### `docs/audit-trail.jsonl` — count column

v0.1.11+ rows include `sub_agent_invocations_count` integer column:
- `0` = field present, empty array (no sub-agents)
- `N` = field present, N sub-agent entries
- `null` = legacy row (pre-v0.1.11, field absent)

**Existing rows are NOT backfilled.** Existing `audit-trail.jsonl` rows are treated as legacy and retain `null` for this column. TeamLead adds the column to new rows going forward.

## §legacy-exemption

Mirrors the `meta` block legacy-exemption pattern (`dispatch-header.md` line 130):

- Dispatches started before v0.1.11 rollout MAY omit `sub_agent_invocations`.
- "Started before rollout" = dispatch was in-flight at time of this addendum landing (commit on `feat/v0.1.11-real-claude-integration` containing AC-5).
- TeamLead identifies legacy dispatches by absence of the field in the return JSON + dispatch_id predating the AC-5 commit timestamp.
- Trigger A does not fire for legacy dispatches even if they were declared parallel-dispatch.

## §scope-decisions

Decisions made during V0.1.11-S1-EX3 (deferred_decisions recorded in return meta):

1. **No per-role notes in po-pm.md / rd-pm.md / qa-pm.md / ux-pm.md / ad-hoc-pm.md**: The `dispatch-header.md` addendum is the canonical location. Duplicating schema into per-role files would create drift risk without adding value — role-specific intake already cross-references the return contract. Decision: canonical-only in `dispatch-header.md`. This is consistent with how `meta` block semantics are also in `dispatch-header.md` without per-role duplication.

2. **Trivial-list initially empty**: Every sub-agent invocation must have a `planaudit_approval_ref` at launch. If operational experience reveals a class of sub-agents so routine they do not need PlanAudit approval (e.g., a general-purpose lookup agent called within a well-scoped read-only step), the trivial-list can be expanded via CCB-Light. Starting empty is the conservative choice — Trigger B fires freely; false positives can be relaxed; false negatives cannot be recovered.

3. **Retry pool separation**: Trigger A and Trigger B each have their own 1-retry pool, distinct from the existing schema-validation pool and step-review pool. This prevents a sub-agent disclosure failure from consuming the schema-validation retry slot (which would escalate to CEO prematurely).

4. **Verifier action on first PM dispatch with this field**: TeamLead should verify the first production dispatch to emit `sub_agent_invocations` by cross-checking the declared `planaudit_approval_ref` anchor actually exists in PROGRESS.md and that the referenced PlanAudit approved the parallel-dispatch pattern. Log result in `## Self-Audit`.
