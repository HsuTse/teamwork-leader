## Anomaly Documentation + Manual Fallback

### I-019 Host Guard

The bash hook on this development host intercepts `launchctl bootstrap` at the CLI level.
This is a host-specific guard; it does not affect production operator deployments where
`launchctl` is invoked by `scripts/install.py` via Python `subprocess.run()` (I-018 mandate).

On a non-guarded production host, the full install flow is:

```bash
# Operator runs (no bash wrapper):
python3 scripts/install.py
```

`install.py` performs the 3-layer install:
1. Write `com.teamlead.daemon.plist` to `~/Library/LaunchAgents/`
2. `launchctl bootstrap gui/$UID <plist_path>` via Python subprocess
3. Write `ThrottleInterval=10` guard; verify daemon is loaded

This path is guard-compliant (Python → subprocess, not raw bash → launchctl).

### BATON_WRITTEN Reaper Note (design.md §1, line 125)

If the daemon process crashes mid-resume (after writing BATON_WRITTEN but before SESSION_RESUMED):

- `lib/gate-lock.py --reap` (subprocess) auto-cleans the stale lock file.
- The daemon main loop calls the reaper periodically — validated by T-4-6 (`--self-test-reaper`).
- On next daemon wake (next `ThrottleInterval` fire), the reaper clears the stale state and
  the poll cycle can re-evaluate gate.lock.

This ensures no permanent lock-file wedge even under daemon crash mid-operation.
